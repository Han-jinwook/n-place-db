- **일시**: 2026-05-18 16:50

## 📜 서문 (Introduction)
본 **멀린 협업 강령(Merlin's Process Creed)**은 대표님과 멀린(AI 어시스턴트)이 바이브코딩 협업 시 세션이 바뀌고 맥락이 리셋되더라도 일관된 작업 품질과 무결성을 유지하기 위해 상시 지켜야 할 **프로세스적 핵심 행동 수칙**을 정의한다.

---

## 🧭 핵심 강령 규칙 (Core Rules)

### 1. 📝 [문서 표준화 강령] 모든 문서의 헤더 필수 명시
- **규칙**: 프로젝트 내에서 작성 및 수정되는 모든 기술 문서, 사양서, 스키마 정의서, 대응 일지(`.md` 파일) 상단에는 무조건 **[제목, 버전, 일시]** 정보가 명확히 머리글(Header)로 기재되어야 한다. 

### 2. 📂 [이슈 일지 보존 강령] help.md 파일명 규칙 준수 및 지시 시 아카이빙
- **규칙**: 개발 중 사용하는 일회성 이슈 대응 일지(`help.md`)는 **오직 대표님의 명시적 지시가 있을 때만** 아카이빙을 진행한다. 아카이빙을 진행할 시에는 반드시 **`help_YYYYMMDD.md` (예: `help_20260518.md`)**와 같이 날짜를 병합하는 파일명 규칙을 철저히 준수하여 `/docs` 폴더 내로 이동 보존한다.

### 3. 💾 [Git 작업 강령] 기능 수정 즉시 로컬 커밋 & 푸시는 지시 시에만 실행
- **규칙**: 
  1. **즉시 커밋**: 코드나 기능 설정을 **하나라도 수정하면 무조건 즉시 Git 커밋을 실행**한다. 이때 커밋 메시지는 대괄호나 접두사(예: `[성공]`, `(성공)`)를 일절 생략하고, 오직 **순수 한글 코멘트**로만 명확히 작성한다.
  2. **푸시 제한**: 원격 저장소로의 푸시(`git push`)는 자의적으로 실행하지 않으며, **오직 대표님의 명시적인 푸시 지시가 있을 때만** 실행한다.

### 4. ⚙️ [배포 일관성 강령] 빌드와 릴리즈 포장의 파이프라인 단일화
- **규칙**: 릴리즈 준비 시 코드 컴파일(`build_exe.py`)과 데이터/계정 정보 정제 및 ZIP 패키징(`prepare_dist.py`)은 무조건 **하나의 통합 파이프라인**으로 일괄 실행되어야 한다. 이를 통해 개별 작업 시 발생할 수 있는 보안 정보 유출 및 패키징 에러를 차단한다.
